# Models and bindings

## First: does it exist?

`grep` the model directory for the concept and read the module list. Reuse
what exists. If yours is genuinely different, say why **in its doc comment**,
naming the one you looked at. Two models of one concept drift apart silently.

## A good model

- **A function, not a restatement**: if the code could not disagree with it, it
  proves nothing.
- **Decision, not effect**: pull the deciding part out of IO and model that; the
  shell around it carries no decision.
- **Total**: answer "nothing" explicitly rather than be undefined.
- **Import, do not duplicate**, what other models compute.

```lean
/-- What a sequence of keys does.

@models REQ-DRIVE.session_is_a_value -/
def drive (keymap : Keymap) (mode : String) : List String → List Step
```

Build it (`lake build`) before anything else. `Imprecise` on a new file: ask the
checker where parsing stopped (`--unparsed <file>`) and write that declaration
more plainly.

## Binding (`.tracelean/drt.json`)

```json
{ "req_id": "REQ-DRIVE", "clause": "session_is_a_value",
  "floors": [{ "situation": "a session of no keys", "atLeast": 20 }],
  "also_checks": ["walk_follows_the_machine"],
  "model": { "import": "Project.Drive", "function": "Project.drive",
             "arguments": ["keymap", "mode", "keys"] },
  "implementation": { "language": "rust", "entry": "src/surface/drive.rs::drive_of" } }
```

- Runners are **generated by the tool** — never write one by hand.
- A `@drt` annotation and a binding must both exist; a test checks they match.
- Keep generated inputs small with varied *shapes*; seed examples with values
  that were wrong before.

## Floors

Agreement alone is not evidence (a do-nothing implementation agrees with
trivial cases). Declare situations to reach — each outcome branch, the empty
case, past bugs — and how often. No floors: stays at L1.

## Running and disagreeing

Slow, behind a flag (`cargo test --workspace -- --ignored`). Run your binding
first. On a divergence, read the shrunk case: the code may be wrong, or the
model may say something the clause does not. Never change the model just to
agree with the code.
