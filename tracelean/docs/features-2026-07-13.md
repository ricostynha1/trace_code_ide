## T0 — Aider Exercism Benchmark Integration

Measures code-editing performance over time and catches regressions in prompts, tool-calling, or execution logic.

### Files

- `scripts/benchmark_exercism.py` — Python runner
- `core/src/ai/benchmark.rs` — Rust structs + `run_benchmark` function

### Metrics Recorded

- Pass/fail rate per task
- Tool calls performed
- Model iterations
- Execution time
- Token usage (input, output, thinking, cached)
- Cost (USD)
- Parsing/tool-calling failures

### Usage

```bash
# Run all default tasks (cost capped at $1)
# Tasks auto-download from exercism GitHub on first run
python scripts/benchmark_exercism.py

# Custom cap
BENCHMARK_COST_CAP=0.50 python scripts/benchmark_exercism.py

# Specific tasks only
python scripts/benchmark_exercism.py hello-world two-fer reverse-string

# Different language track
EXERCISM_LANGUAGE=rust python scripts/benchmark_exercism.py
```

Output: `benchmark_results.json` (JSON matching the `BenchmarkRun` struct).

### Rust API

```rust
use tracelean_core::ai::benchmark::{run_benchmark, BenchmarkConfig};

let config = BenchmarkConfig {
    cost_cap_usd: 1.0,
    task_names: vec!["hello-world".into()],
};
let result = run_benchmark(config, |task_name| { /* execute task */ });
println!("Pass rate: {:.0}%", result.pass_rate() * 100.0);
```

## T1 — Model Metadata JSON Generation

Build-time Python scripts that fetch model data from external sources and output static JSONs consumed by the Rust app at runtime.

### Files

- `scripts/fetch_model_metadata.py` — fetcher script
- `scripts/requirements.txt` — Python deps (`requests`)
- Output: `data/model_pricing.json`, `data/model_rankings.json`

### Sources

- **LiteLLM** (`model_prices_and_context_window.json`) — pricing, context window, prompt caching support, tool calling
- **llm-stats.com API** (`GET /v1/rankings?category=coding`) — TrueSkill coding performance rankings

### API Setup

Get a free API key at https://llm-stats.com/developer (keys start with `ze_`).

```bash
export LLM_STATS_API_KEY=ze_your_key_here
```

### Output Schema

`data/model_pricing.json` — array of:
```json
{
  "model": "anthropic/claude-sonnet-5",
  "provider": "anthropic",
  "pricing": { "input_per_1m_tokens": 3.0, "output_per_1m_tokens": 15.0 },
  "context_window": 200000,
  "supports_prompt_caching": true,
  "supports_tool_calling": true,
  "supported_endpoints": ["..."],
  "release_info": "..."
}
```

`data/model_rankings.json` — array of (ranked by TrueSkill score):
```json
{
  "model_id": "claude-4-sonnet",
  "model_name": "Claude 4 Sonnet",
  "organization": "anthropic",
  "score": 94.2,
  "conservative_rating": 91.0,
  "rank": 1,
  "open_weight": false,
  "benchmarks_evaluated": 5,
  "min_input_price": 3.0
}
```

### Notes

- Claude models may report wrong endpoint (litellm uses bedrock-specific paths, not `/v1/chat/completions`)
- `supports_prompt_caching` comes from litellm's `supports_prompt_caching` field
- Order is stable: ranked by TrueSkill coding score from llm-stats.com
- Fallback: if /rankings fails, uses /models catalog `top_scores.coding` field

### Usage

```bash
pip install -r scripts/requirements.txt
export LLM_STATS_API_KEY=ze_your_key_here
python scripts/fetch_model_metadata.py
```

## T2 — Tool Call Visualization in Chat

Groups consecutive tool calls made within a single model response into a compact summary.

### Behavior

- **Same response**: `[batch] call read_lines ×3, write_file ×1`
- **Separate responses**: Each appears as its own line (no grouping)

The distinction: if an `assistant` message appears between tool call messages, they belong to different model responses and render separately.

### How It Works

In `AiChatPanel.tsx`, the message rendering detects consecutive `role='system'` messages. Groups them by extracting tool names (from patterns like `→ tool_name(...)` or `call tool_name`) and shows a collapsed batch with counts.

### Visual

```
[batch] call read_lines ×10, write_file ×2
assistant: Here's the result...
call read_lines ×1
```

The first line = one model response made 12 tool calls. The third line = a separate model response made 1 call.

## T3 — Chat Switching (Replaces "New Chat")

The `+` button no longer clears the current chat. It opens a dialog to switch between active chat sessions.

### Behavior

- Click `+` → opens Chat Switcher modal
- Modal shows all chat instances: first message preview, message count, timestamp
- Click a chat → switch to it (current chat is saved)
- Drag-and-drop to reorder chats
- "New Chat" button inside the dialog creates a fresh session

### Files

- `react_frontend/components/ChatSwitcher.tsx` — modal component
- `react_frontend/components/AiChatPanel.tsx` — state management (`chatInstances`, `activeChatId`)
- `react_frontend/App.css` — styling

### State Model

```typescript
interface ChatInstance {
  id: string;
  messages: ChatMessage[];
  createdAt: Date;
  label: string;
}
```

All chats persist in component state. Switching saves current messages to the active instance and loads the selected one. No backend changes needed — chat history is frontend-only.
